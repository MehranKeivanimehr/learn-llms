## From token to vector

A model can't do math on the text "queen". So the first thing it does is look up each token in a big table and replace it with a list of numbers called an **embedding** (or vector). Real models use hundreds or thousands of numbers per token. We'll use just two, so we can draw them on a map.

Nobody writes these numbers by hand. They are learned during training, and something remarkable happens: tokens with related meanings end up pointing in **similar directions**.

## Measuring similarity

To compare two vectors, models often use **cosine similarity**: how closely do the two arrows point the same way? It's 1 for exactly the same direction, 0 for a right angle and −1 for opposite directions. The length of the arrows doesn't matter — only the direction.

## Directions carry meaning

In well-trained embeddings, directions can mean something. Going from "man" to "woman" is a step in one direction; going from "king" to "queen" is roughly the same step. That's why the famous trick works:

**king − man + woman ≈ queen**

Real embedding spaces are messy, and this works only approximately — but it shows that the model has organized meaning into geometry.
